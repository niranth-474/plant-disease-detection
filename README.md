# Plant Disease Detection

A FastAPI service backed by the existing PyTorch CNN, with a separate responsive HTML/CSS/JavaScript frontend. The browser can upload a leaf image or capture a still webcam frame; predictions are generated by the trained model, not by the frontend.

## Project layout

- `model/` contains dataset, training, evaluation, and command-line prediction code.
- `backend/services/prediction_service.py` loads the checkpoint once and shares preprocessing/inference with the CLI.
- `backend/web.py` exposes health and versioned prediction endpoints.
- `frontend/` contains the static browser interface.
- `tests/` contains standard-library `unittest` tests; successful inference tests use the local trained checkpoint and do not need the dataset.
- `saved_models/` contains local model artifacts. Do not commit model weights or the PlantVillage dataset.

## Model files

The API and CLI require both:

- `saved_models/best_model.pth` — checkpoint created by `model/train.py`
- `saved_models/class_names.json` — ordered class labels created by training

The checkpoint must contain `model_state_dict`, `num_classes`, and (for current checkpoints) `class_names`. The prediction service validates these against the class-name file and classifier output layer at startup. If the files are missing or incompatible, the server starts with `model_loaded: false`; prediction requests return HTTP 503. The dataset at `PlantVillage/` is only required for training and evaluation.

The checkpoint currently in this workspace advertises **15 classes**, and its stored class names match `saved_models/class_names.json`. The specification mentioned 38 classes, but these current weights do not support those additional classes. To predict all 38 PlantVillage classes, train a 38-class model and replace both model artifacts together.

Training and inference share `IMAGE_SIZE` and ImageNet normalization from `model/config.py`. Training selects the best checkpoint using validation accuracy; the held-out test set remains for evaluation only.

## Start the application (PowerShell)

Run these commands from the project directory in separate terminals:

```powershell
.\myenv\Scripts\python.exe -m uvicorn backend.web:app --reload
```

```powershell
.\myenv\Scripts\python.exe -m http.server 5500 --directory frontend
```

Then open:

- Frontend: [http://127.0.0.1:5500](http://127.0.0.1:5500)
- API health: [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)
- API documentation: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- Prediction endpoint: `POST http://127.0.0.1:8000/api/v1/predict`

The prediction endpoint accepts a multipart form upload named `file` and returns the predicted class, confidence, and up to three ranked predictions. Images larger than 10 MB or 20 megapixels are rejected.

Camera permission is available on `localhost`/`127.0.0.1` or an HTTPS deployment. The frontend uses `getUserMedia()` only after the user selects **Start camera**. Capture creates one still image for prediction; the app does not run continuous webcam inference. Camera tracks are stopped when the user presses **Stop camera**, captures a frame, or leaves the page.

For a different API host, update `API_BASE_URL` in `frontend/js/script.js` and set the frontend origin in the API host's `FRONTEND_ORIGINS` environment variable.

### Deploying with Hugging Face model files

The API downloads `best_model.pth` and `class_names.json` from the Hugging Face **model repository** below during application startup, then loads and validates them once:

`niranthanand/plant_disease_detection`

The files must be at the repository root and use those exact names. You can set `HF_MODEL_REPO_ID` on the hosting provider if you use another repository. For a private or gated repository, set `HF_TOKEN` as a secret environment variable; never put the token in source code. Public repositories do not need a token. The host needs outbound access to `huggingface.co`, and its disk/cache must be large enough for the checkpoint. A model download or load failure is logged at startup and reported by health checks as `model_loaded: false`.

For a separately hosted static frontend, set `API_BASE_URL` in `frontend/js/script.js` to the public HTTPS base URL of the API (no `/api/v1/predict` suffix). On the API host, set `FRONTEND_ORIGINS` to the exact frontend origin, for example `https://your-site.vercel.app`. Multiple allowed origins may be comma-separated. Localhost origins remain enabled for development.

## Run tests and check the environment

```powershell
.\myenv\Scripts\python.exe -m unittest discover -v
.\myenv\Scripts\python.exe -m scripts.check_environment
```

The environment check imports PyTorch and torchvision, reports CUDA availability, and runs a sample inference when the checkpoint is present. It does not change Windows security settings or reinstall PyTorch.

## Train or evaluate

Place the PlantVillage class-folder dataset in `PlantVillage/`. Use the existing environment and run commands from the project root:

```powershell
.\myenv\Scripts\python.exe -m model.train
.\myenv\Scripts\python.exe -m model.evaluate
.\myenv\Scripts\python.exe -m model.predict path\to\leaf.jpg
```

Install the dependencies in `requirements.txt` if needed. PyTorch and torchvision must be a compatible pair for the desired CPU/CUDA setup; use the official PyTorch installation selector for the machine rather than replacing an already working installation blindly.
